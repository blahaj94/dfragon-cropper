# 설정과 데이터

[제품 소개](../README.md) · [문서 목록](README.md)

Portable 앱의 설정·캡처·로그는 임시 extraction 폴더가 아닌 실행 EXE 옆에 저장됩니다. EXE가 있는 폴더에 쓰기 권한이 필요합니다.

## 파일 위치

| 데이터              | 개발 실행                     | Portable 실행            |
| ------------------- | ----------------------------- | ------------------------ |
| 프로필 설정         | `.dev-config/config.json`     | EXE 옆 `config.json`     |
| 직전 유효 설정 백업 | `.dev-config/config.json.bak` | EXE 옆 `config.json.bak` |
| 캡처 파일           | `.dev-captures/`              | EXE 옆 `captures/`       |
| 진단 로그           | `.dev-logs/app.log`           | EXE 옆 `logs/app.log`    |

개발 모드에서만 `DFRAGON_CONFIG_FILE`로 설정 파일 위치를 바꿀 수 있습니다. Portable 실행에서는 이 환경 변수를 사용하지 않습니다. 위 로컬 데이터는 Git 추적 대상이 아닙니다.

## 설정 형식과 저장

`config.json`은 `schemaVersion: 2` JSON입니다. 프로필·ROI·활성 프로필·ID 증가 카운터와 `preferences.saveOriginal`, `preferences.closeToTray`를 저장합니다. 두 옵션은 정확한 boolean 값이어야 하며 기본값은 모두 `true`입니다.

프로필과 ROI ID는 변경하거나 삭제 후 재사용하지 않습니다. 좌표는 Primary Monitor의 물리 픽셀을 나타내는 안전한 정수로, `x/y >= 0`, `width/height > 0`이어야 합니다. 이름·좌표·명령·설정 데이터는 main에서 검증합니다.

설정과 백업이 모두 없는 첫 실행에는 기본 설정을 만듭니다. 정상 설정을 변경할 때는 직전 유효 설정을 `config.json.bak`에 보존한 뒤 임시 파일의 새 설정을 원자적으로 교체합니다. 백업은 한 세대만 유지되며 최초 실행 직후에는 없을 수 있습니다. 저장에 실패하면 메모리의 설정도 성공한 것처럼 변경하지 않습니다.

앱은 같은 사용자 데이터 폴더에서 중복 인스턴스를 막고 저장 직전 외부 변경을 검사합니다. 외부 편집기 등 다른 프로그램과의 동시 쓰기를 막는 범용 파일 잠금이나 원자적 compare-and-swap을 제공하지는 않습니다. 설정 파일을 직접 교체하거나 편집하려면 먼저 `Quit`로 앱을 완전히 종료하세요.

### v1 설정 이관

완전히 유효한 v1 설정만 자동으로 v2로 이관합니다. 기존 프로필·이름·ID·증가 카운터·활성 선택은 유지하고 두 새 옵션을 켭니다.

이관 전에 정확한 v1 원문을 `config.json.bak`에 보존한 뒤 v2 파일을 원자적으로 교체합니다. 이관에 실패하면 성공한 설정을 메모리에 게시하거나 잘못된 원본을 덮어쓰지 않습니다. v2 파일을 다시 여는 것만으로 백업을 교체하지 않으며, 이후 정상 저장부터 직전 유효 v2 설정으로 백업을 갱신합니다.

## 오류가 발생했을 때

유효한 설정을 사용하던 중 일반적인 저장 실패가 발생하면 폼에 오류를 표시하고 이전에 저장된 설정을 유지합니다. 이전 설정이 유효하면 캡처는 계속 사용할 수 있습니다.

다음은 설정을 신뢰할 수 없는 오류로 처리하며 프로필 편집과 앱 캡처를 차단합니다. Windows의 기본 PrintScreen 입력 전달은 유지됩니다.

- 잘못된 JSON, 지원하지 않는 schema version 또는 유효하지 않은 값
- 앱 실행 중 발견된 외부 설정 변경
- `config.json`은 없지만 `config.json.bak`은 있는 복구 상황

앱은 이러한 파일을 덮어쓰거나 기본값으로 초기화하지 않습니다. 백업을 자동 복원하거나 손상 파일을 자동 삭제하지도 않습니다.

### 백업으로 수동 복구

1. `Quit`로 앱을 완전히 종료합니다. 창의 닫기 버튼만 누르면 트레이에서 실행 중일 수 있습니다.
2. 손상되었거나 지원되지 않는 `config.json`이 있으면 다른 이름이나 폴더로 복사해 별도로 보존합니다. 복구 전에 원본을 삭제하지 않습니다.
3. `config.json.bak`이 이전의 유효한 설정인지 확인하고, 백업 파일은 남겨 둔 채 그 내용을 `config.json`으로 복사합니다.
4. 앱을 다시 실행해 프로필, 활성 선택과 ROI를 확인합니다. 백업도 유효하지 않으면 계속 오류 상태로 두고 다른 유효한 설정 사본을 복구합니다.

## 캡처 파일과 로그

캡처마다 별도 이벤트 폴더에 ROI PNG들과 `metadata.json`을 저장합니다. `Save original PNG`가 켜져 있으면 `original.png`도 저장합니다. 원본 저장을 끈 이벤트의 metadata에는 원본 파일이 없음을 기록하며 이력에서는 ROI 이미지를 열 수 있습니다.

프로필과 원본 저장 옵션을 바꿔도 이전 캡처를 삭제하지 않습니다. 이력 화면은 최근 100개만 표시하지만 오래된 파일을 자동 삭제하지 않습니다. Portable 앱은 이전 버전의 `.dev-captures/`도 읽되, 같은 이벤트 ID가 새 `captures/`에도 있으면 새 경로를 우선합니다. 기존 파일은 이동하거나 삭제하지 않습니다.

`config.json.bak`은 설정 백업입니다. 캡처 파일을 백업하거나 캡처의 버전 이력을 관리하는 기능은 아닙니다.

0.5.0의 `Ground Truth` 탭은 각 이벤트의 `metadata.json`에 ROI별 정답 텍스트를 저장하고, 직전 정상본을 `metadata.json.bak`으로 보관합니다. 백업은 직전 한 세대이며 PNG 파일의 백업은 아닙니다. 정답은 문자열 또는 `null`이며 별도 완료 플래그를 두지 않습니다. 기존 캡처 필드와 PNG 파일은 보존합니다. [정답 작성·저장·복구 안내](ground-truth.md)를 참고하세요.

진단 로그 `app.log`는 5 MiB를 넘으면 `app.previous.log`로 한 세대만 보관합니다. 로그 저장 실패가 이미 성공한 캡처 결과를 실패로 바꾸지는 않습니다. 문제를 확인할 때 metadata와 로그를 함께 참고하되, 개인 화면·경로가 포함된 로컬 자료를 Git에 추가하지 마세요.
