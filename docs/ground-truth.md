# 이미지별 정답 작성

[문서 목록](README.md) · [사용 가이드](user-guide.md)

현재 개발 소스의 `Ground Truth` 탭에서 캡처 결과 이미지에 캐릭터 닉네임을 작성합니다. 이 기능은 기존 0.4.0 릴리스 실행 파일에는 포함되지 않습니다. 사람이 정답 텍스트를 입력하는 로컬 기능이며 OCR 추론이나 서버 전송을 수행하지 않습니다.

## 작업 흐름

1. 먼저 필요한 화면을 캡처해 모아 둡니다.
2. `Ground Truth` 탭을 엽니다. 오래된 캡처부터 제목 아래에 각 ROI 이미지와 닉네임 입력칸이 이어집니다. 아래로 스크롤하면 다음 캡처들을 불러옵니다. 기존 `Captures` 탭의 최근 100개 제한과 별개로 과거 캡처도 접근할 수 있습니다.
3. 이미지 오른쪽에 캐릭터 닉네임을 입력하고 해당 행의 `Save`를 누릅니다. 캡처당 이미지 개수와 관계없이 한 이미지씩 저장합니다.
4. Enter를 누르면 그 이미지의 저장에 성공한 뒤 다음 미작성 이미지의 입력칸으로 이동합니다. 한글 등의 입력기를 조합 중인 Enter는 정답을 저장하지 않습니다.
5. 왼쪽 목차에서 캡처를 누르면 오른쪽의 해당 위치로 이동합니다. 목차에는 불러온 캡처가 표시되며 다른 캡처도 계속 펼쳐져 있습니다.

이미지의 표시 크기를 바꿔 작은 글자를 확인할 수 있습니다. 표시용 확대만 수행하며 원본·ROI PNG의 픽셀과 파일은 변경하지 않습니다. 화면 근처의 이미지를 불러오고, 멀어진 이미지는 메모리에서 해제합니다. 작성 중인 텍스트는 이미지 로딩과 별도로 유지되므로 스크롤하거나 탭을 바꿔도 사라지지 않습니다. 저장하지 않은 텍스트는 앱 종료 후에는 복구되지 않습니다.

## 표시 옵션

- **Hide images with answers:** 저장된 정답 텍스트가 있는 이미지 행을 숨깁니다. 작성 중이거나 저장에 실패한 입력은 유지합니다. 저장에 성공한 결과에만 숨김 조건을 적용합니다.
- **Show empty capture headings:** 필터 때문에 보이는 이미지가 없어진 캡처도 제목과 왼쪽 목차 항목을 남깁니다. 끄면 둘 다 숨깁니다.

두 옵션은 화면 표시를 조절하며 metadata에 완료 여부나 `enabled` 값을 기록하지 않습니다. 완료 여부는 저장된 정답이 `null`인지로 판단합니다. 기존 파일에 정답 필드가 없으면 미작성입니다. 닉네임을 지우고 저장하면 `null`이 되며, 공백만 입력한 경우도 동일합니다. 문자가 포함된 입력은 공백을 포함해 그대로 저장합니다.

## metadata 저장

정답은 프로필의 ROI 설정이 아니라 **특정 캡처 이벤트의 특정 ROI 이미지**에 속합니다. 같은 ROI ID가 다른 캡처에 있어도 정답은 독립적입니다. 각 이벤트 폴더의 `metadata.json`에 다음 선택적 영역을 추가합니다.

```json
{
  "groundTruth": {
    "schemaVersion": 1,
    "regions": {
      "1": "용기사",
      "2": null,
      "3": "캐릭터 이름"
    }
  }
}
```

위 예시는 추가되는 영역만 표시합니다. 최상위 `schemaVersion: 1`, 원본 정보와 해시, 프로필, ROI 좌표·파일명 등 기존 필드는 보존합니다. 이전 앱은 정답 필드를 사용하지 않지만 캡처 이력을 계속 읽을 수 있습니다. 정답 변경은 향후 캡처에 사용할 프로필과 좌표에 영향을 주지 않습니다.

저장할 때 직전 정상 metadata의 정확한 내용을 `metadata.json.bak`에 보관하고, 완성된 임시 파일로 metadata를 교체합니다. 백업은 직전 한 세대이며 정답 편집의 전체 이력은 아닙니다. 저장에 실패하면 성공으로 표시하거나 다음 이미지로 이동하지 않고, 입력을 유지합니다.

외부 변경을 발견하면 덮어쓰기를 중단합니다. 해당 캡처의 저장된 정답을 다시 불러와 현재 입력과 비교한 뒤 저장하세요. 원본 JSON 손상이나 지원하지 않는 정답 형식은 자동으로 초기화하지 않습니다. metadata를 직접 편집하거나 백업으로 복구할 때에는 앱을 종료하고, 손상 파일과 백업을 별도로 보존하세요. 앱 내부의 저장 순서는 관리하지만 외부 프로그램과의 동시 편집을 위한 파일 잠금을 제공하지는 않습니다.
