# 서버 연동 명세 준비

[문서 목록](README.md)

현재 앱은 로컬 저장만 지원합니다. 연결할 서버의 저장소나 OpenAPI 문서가 정해지면 아래 항목을 확인해 업로드 계약을 확정합니다. 이 문서는 필요한 정보를 정리한 목록이며, 구현된 서버 API 명세가 아닙니다.

## 서버에서 정할 내용

| 항목        | 필요한 정보                                                                                           |
| ----------- | ----------------------------------------------------------------------------------------------------- |
| 연결·인증   | 환경별 기본 URL, API 버전, 인증 방법과 자격 증명 갱신·만료 처리                                       |
| 업로드 단위 | 한 캡처 이벤트의 PNG·메타데이터를 함께 전송할지, 파일별 업로드 뒤 이벤트를 확정할지                   |
| 크기 제한   | 파일·이벤트 크기, ROI 개수 제한, 타임아웃. 원본 픽셀을 보존해야 하므로 초과 파일을 자동 축소하지 않음 |
| 응답        | 서버 이벤트·파일 ID, 완료 상태, 검증 실패와 부분 실패의 표현                                          |
| 중복·재시도 | 재전송 시 중복 생성을 막는 키, 재시도할 오류, 대기 시간과 제한                                        |
| 보관        | 서버 보관·삭제 정책, 로컬 파일과 서버 파일의 관계                                                     |

앱의 업로드 시작 방식도 함께 결정해야 합니다. 사용자 요청으로 보낼지 자동으로 보낼지, 오프라인 보관과 재시작 후 재전송을 지원할지 정합니다. 로컬 캡처 성공과 업로드 성공은 별도로 표시해야 합니다.

## 현재 앱이 가진 데이터

완료된 이벤트 폴더에는 각 ROI의 PNG와 `metadata.json`이 있습니다. 원본 저장 옵션이 켜져 있을 때만 `original.png`가 있습니다. metadata를 마지막에 쓰므로 업로드 대상은 저장을 완료한 이벤트여야 합니다.

metadata의 현재 `schemaVersion`은 1이며 다음 정보를 담습니다.

- 로컬 `eventId`, ISO 형식의 `capturedAt`, 캡처 계기 `trigger`
- 캡처 시작 시 고정한 프로필의 `id`와 `name` (현재 앱은 포함하며, 이전 이벤트에는 생략될 수 있음)
- `coordinateSpace: primary-monitor-physical-pixels`
- 원본의 크기, 픽셀 형식, 캡처 backend, `rgbaSha256`, 파일명
- 각 ROI의 고정 ID, `x / y / width / height`, 파일명

원본을 저장하지 않은 이벤트는 원본 파일이 없고 `source.file`은 `null`입니다. 서버는 이를 허용하거나 필요한 정책을 명시해야 합니다. 없는 원본을 나중에 다시 캡처해서 같은 이벤트에 붙일 수는 없습니다. 모든 ROI는 당시 동일한 한 프레임에서 만들어졌습니다.

`rgbaSha256`은 원본의 **디코딩된 RGBA 바이트** 해시로, PNG 파일 바이트의 해시가 아닙니다. 전송 파일의 무결성을 확인하려면 파일별 해시 알고리즘과 대상 바이트를 별도로 정해야 합니다.

## 식별자와 전송 경계

로컬 이벤트 ID와 프로필 ID를 서버 전체에서 유일하다고 가정하지 않습니다. ROI ID는 프로필 안에서 식별하며, 서버는 계정·기기 범위와 중복 방지 규칙을 정해야 합니다.

업로드에는 확정된 필드만 포함합니다. 내부 `CaptureResult`나 `CaptureSummary`를 그대로 직렬화하면 `outputDirectory`와 ROI `path` 등 PC의 절대 경로가 포함될 수 있습니다. 프로필 이름과 기기 정보의 전송 여부도 명세에 명시합니다. 실제 화면을 서버로 보내는 기능은 이 계약과 사용자 동작이 정해진 뒤 추가합니다.
