# Agent instructions

- Read `README.md`, `docs/development.md` and `spike/windows-capture/README.md` first. Keep the root README short: a brief introduction, download link, three usage steps with real app screenshots, and compact documentation links. Use non-private example data for screenshots and state their provenance. Put architecture, feature tables, data schemas, development instructions and detailed verification limits under `docs/`, not in the README.
- The local Windows MVP includes numeric and preview-drag ROI editing, profiles, explicit draft saves, recent capture history, original-PNG preference, tray/background behavior, explicit quit, single-instance handling and diagnostic logs. Version 0.4.0 adds F12 frameless fullscreen frozen-screen ROI selection with a cursor magnifier, existing-ROI redraw into numeric drafts and Fit/100% history viewing; Windows builds/distribution are automated. Do not add servers/uploads before the server integration details are supplied and authorized; OCR, authentication, multi-monitor capture, a DB, generic event bus and plugin framework remain outside scope.
- Keep the profile selected for editing separate from the active capture profile. Unsaved name/coordinate drafts must not affect captures. Each capture snapshots the saved active profile ID/name and ROI list before taking its one source frame. No active profile, no saved ROI or a settings error must block app capture while preserving normal Windows PrintScreen forwarding.
- The Ground Truth workspace is manual, local nickname transcription on already-saved ROI images. Show oldest-first capture groups in a continuous paged feed with bookmark navigation; the existing Captures tab still has its separate latest-100 policy. Save each ROI's string or null in optional metadata.groundTruth (schemaVersion 1), preserving all other metadata and every PNG. Derive completion from text, never persist enabled/completed flags. Blank saves clear to null. Keep drafts across scrolling, filtering and tab changes; Enter advances only after a successful save and must not submit an IME composition. Hide answered rows from saved state and optionally retain empty capture headings/bookmarks. Keep ground-truth persistence and renderer drafts in their own domain modules; app entry/IPC only wire or validate transport. Preserve old metadata reads, pin the physical event folder, reject stale writes, retain a one-generation backup and publish atomic replacements. Do not claim universal external-writer exclusion.
- Profile and ROI IDs are immutable safe integers and must never be reused after deletion. Coordinates are safe integers with x/y >= 0 and width/height > 0. Validate names, command shapes and all configuration data in main; renderer validation is not a trust boundary. Preserve the initial Default profile's two ROIs.
- Use schemaVersion 3 in config.json beside the portable EXE; development defaults to .dev-config/config.json and only development honors DFRAGON_CONFIG_FILE. Preferences saveOriginal and closeToTray are exact booleans, enabled by default. Store capture/selectRoi bindings in top-level shortcuts, defaulting to PrintScreen/F12. Migrate only fully validated v1/v2 config, retaining profiles, names, IDs, counters, active selection and existing v2 preferences, and preserving the exact old text in config.json.bak before publishing v3. Add enabled preferences only for v1. Older apps cannot read v3; downgrade requires an old valid config copy with the app closed. Save through temporary files and atomic replacement. A failed save/migration must not publish an in-memory success or overwrite an invalid original.
- An ordinary save failure against otherwise valid settings is a form error: preserve the saved state and allow captures from it. Do not confuse this with corrupt/unsupported/external-change errors that block editing and capture. Single-instance handling prevents duplicate app writers/listeners within the same userData; the pre-save external-change check is not a cross-process file lock or atomic compare-and-swap guarantee against other programs.
- Corrupt/unsupported configuration or detected external changes must not be silently overwritten, reset or auto-restored. Block editing/capture and report the error. A missing config with an existing backup is a recovery case, not a fresh installation. Document manual recovery with the app closed, damaged file preserved, and a copy of the valid backup restored to config.json.
- Physical pixel preservation is the core product contract. Never resize, filter, normalize, sharpen, grayscale or use lossy encoding. Crop by copying exact rows from one immutable source frame per event.
- Preview display scaling is presentation only. Convert drag positions against the original preview frame dimensions into validated physical integer rectangles inside the fullscreen overlay; never resample the actual capture or ROI PNGs. Redrawing an existing ROI updates the same numeric draft and preserves its ID; only explicit save changes capture coordinates. Cancelled gestures must preserve existing drafts. A 100% image view uses one image pixel per CSS pixel, not necessarily one physical display pixel under OS scaling. Snapshot saveOriginal with the capture profile so an in-flight event cannot change output policy. History displays at most 100 recent events and must not automatically delete older data.
- Primary Monitor only, absolute nonnegative physical pixel coordinates. Multi-monitor capture and virtual-screen coordinates are intentionally out of scope. Thread DPI awareness prevents coordinate virtualization; it is not a multi-monitor feature.
- Do not replace the capture or PrintScreen implementation without evidence. Preserve baseline experiments and record the reason for any replacement.
- Never claim native capture, cursor exclusion, DPI behavior or PrintScreen behavior is verified without actual Windows evidence. Label synthetic input and synthetic frames explicitly.
- Prefer reasoning/code inspection for scaffolding and simple changes. Use meaningful unit tests for pixel/data contracts, then Playwright for normal UI, then native fixtures/Windows tests. Repeat verification only for a changed contract or new uncertainty.
- Use Playwright before computer-use for UI. Computer-use is a last resort when scripts, native fixtures and other appropriate methods cannot verify the interaction.
- Keep `contextIsolation: true`, `sandbox: true` and `nodeIntegration: false`. Renderer only gets named typed preload methods. Validate IPC sender/frame/URL and arguments in main. No renderer filesystem/native API access.
- Keep `src/main/index.ts` as the composition root: wire lifecycle, desktop adapters and domain controllers there. Capture eligibility, profile mutations/persistence and history policies belong in their domain modules. IPC checks transport identity/arity and delegates domain validation. Share helpers only when callers share the same contract; keep renderer draft/gesture state near its feature rather than adding generic global utilities. See `docs/code-structure.md` for ownership boundaries.
- Native callbacks must promptly pass PrintScreen and unrelated input onward; keep capture and disk work outside keyboard callbacks. Capture shortcuts always pass through; the optional configured ROI shortcut (default F12) consumes only its matching base-key down/up so the foreground program cannot change the screen before selection. Without that callback, the ROI key is forwarded too. Apply only saved bindings, match modifiers exactly, reject duplicate/unsafe bindings and preserve held-key tracking across modifier or binding changes. PrintScreen is reserved for pass-through capture, never ROI selection. Keep shortcut state/validation in dedicated modules. Release native resources and hook registrations on exit.
- Keep portable.unpackDirName enabled: electron-builder 26.15.3 then extracts each launch into its own temporary folder, allowing a second portable launch to reach Electron's single-instance handler without replacing running files.
- Closing to tray must preserve capture availability; explicit Quit must finish in-flight capture/config writes and exit instead of hiding. Do not hide the only accessible window if tray creation fails. New tray/background and preview-coordinate behavior requires appropriate evidence rather than assuming earlier spike checks cover it.
- Portable outputs use captures/ and logs/ beside the outer EXE, not its temporary extraction directory. Read legacy .dev-captures/ history without moving/deleting files, preferring captures/ for duplicate event IDs. Development captures, config/backups and logs use ignored .dev-captures/, .dev-config/ and .dev-logs/. Rotate app.log above 5 MiB to one app.previous.log; logging failure must not turn a successful capture into failure. Never commit personal config files, screenshots, logs, private host names, usernames, absolute personal paths, credentials, keys or environment notes. Local .codex/ is ignored.
- For the current end-to-end MVP request, the user explicitly authorized committing and pushing directly to the repository default branch without creating a PR; this supersedes the earlier codex/ feature-branch rule. Do not force-push, merge unrelated work or overwrite another worker's changes.
- Before feature delivery run lint, format check, typecheck, relevant unit tests, Playwright UI tests and Electron build; install dependencies when the dependency/lockfile state requires it. Exercise persistence failure/recovery and IPC validation with meaningful tests. Preserve earlier native evidence as historical evidence and record new Profile Editor checks separately; do not claim new checks passed before running them.
